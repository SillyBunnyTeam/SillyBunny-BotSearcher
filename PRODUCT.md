# Product

## Register

product

## Users

BotSearcher is primarily for SillyBunny users who want to find and import character cards from supported public catalogs without leaving SillyBunny. They need clear search controls, useful source and content information, and direct guidance when a source or required component is unavailable.

Operators and maintainers are the secondary audience. They install the server plugin, manage its configuration, diagnose source failures, and verify releases.

## Product Purpose

BotSearcher lets users search supported character-card sites, inspect the details those sites provide, and import selected cards into SillyBunny. Search and proxy-thumbnail requests run through the user's SillyBunny server rather than a public relay. The product should state the limits of that routing and distinguish source-reported details from contents verified during import.

Success means users can find and import a card, understand what information is known about it, and recover from common setup or source errors without having to understand the implementation.

## Brand Personality

Plain, direct, and factual. Copy should use ordinary words, short sentences, and specific actions. It should sound calm and competent without sales language, jokes, metaphors, rhetorical flourishes, or self-congratulation.

## Anti-references

Avoid promotional landing-page copy, chatty assistant language, theatrical status messages, and essay-like explanations built around contrasts or asides. Do not make absolute privacy or safety assurances. Do not expose upstream API names when a clear user-facing label is available.

## Design Principles

1. Put the user's task first. Labels and status text should explain the current state and the next useful action.
2. Scope every claim. Say what the extension, server, selected source, and browser each receive or do.
3. Separate reported facts from verified facts. Unknown or unavailable information must not be presented as absent or safe.
4. Keep technical detail where it helps setup or recovery. Prefer familiar product terms elsewhere.
5. Preserve source content as source content. Product copy must not rewrite character-card text or imply that BotSearcher authored it.

## Accessibility & Inclusion

Interactive controls need durable accessible names rather than placeholder-only labels. Status changes and errors should remain understandable to screen-reader users, and instructions must not depend only on hover text, color, or visual position. Copy should support keyboard workflows, text expansion, and plain-language comprehension.
